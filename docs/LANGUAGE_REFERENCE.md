# LIR Language Reference (generated)

Generated by `lir lang --markdown`. Do not edit by hand: change
`src/bootstrap/langref.zig` and regenerate. Every `supported` example below
is compiled and executed by `zig build test`.

Status: **supported** = safe to generate, **partial** = read the notes,
**legacy** = accepted but prefer the canonical spelling, **unsupported** = rejected.

## Reserved words

Never emit these as identifiers, parameter names, field names or function
names. The list comes from the lexer (`lir lang --keywords --json`,
schema `lir.keywords.v1`) and includes words that are reserved but not
implemented (`async`, `await`, `unsafe`, `asm`, `extern`, `mod`, `i128`, …).

## Declarations

### `fn` — supported

```lir
fn name(p: T, q: T = default) -> T { ... }
```

Top-level only: no nested/named-inner functions. Every non-void function must return a value on all paths. Statements are newline separated; ';' is optional and rarely needed. Maximum 8 parameters.

**Avoid:** nested 'fn' inside a body, closures declared with 'fn(x){}'; use |x| ... for lambdas

```lir
fn add(a: i64, b: i64) -> i64 {
    return a + b
}

fn main() -> i64 {
    printInt(add(2, 3))
    return 0
}
```

### `proc` — legacy

```lir
proc name(...) -> T { ... }
```

Alias of 'fn' kept for older code. New code must use 'fn'.

**Prefer:** fn

```lir
proc twice(x: i64) -> i64 {
    return x * 2
}

fn main() -> i64 {
    return twice(21)
}
```

### `const_global` — supported

```lir
const NAME: i64 = value
```

Global constants only; there are no global mutable variables. The type annotation is optional. Constant expressions may use arithmetic, '**' and comptime calls.

**Avoid:** top-level 'let'/'var'; they are rejected with a hint to use 'const'

```lir
const LIMIT: i64 = 3 ** 4

fn main() -> i64 {
    return LIMIT - 81
}
```

### `struct` — supported

```lir
struct Name { field: T }
```

Fields are newline separated, not comma separated. Field declarations may not name another struct type (use a pointer to it). Layout is 8-byte slots with documented offsets (lir ast shows them). Maximum 32 fields.

**Avoid:** struct A { b: B }  (field of struct type); store *B instead

```lir
struct Point {
    x: i64
    y: i64
}

fn main() -> i64 {
    let p = Point { x: 3, y: 4 }
    return p.x * 10 + p.y
}
```

### `enum` — supported

```lir
enum Name { A, B(i64), C(i64, bool) }
```

Variants are comma separated. A variant may carry up to 8 payload fields. Construct with Name::Variant(...), compare with ==. Matching an enum requires exhaustive arms.

```lir
enum Shape {
    Circle(i64),
    Empty,
}

fn main() -> i64 {
    let s = Shape::Circle(7)
    return match s {
        Shape::Circle(r) => r * 2,
        Shape::Empty => 0,
    }
}
```

### `union` — supported

```lir
union Name { i: i64 f: f64 }
```

Untagged C-style union of 8-byte slots. Reading a field other than the one written is not type-checked.

```lir
union Bits {
    i: i64
    f: f64
}

fn main() -> i64 {
    let b = Bits { i: 5 }
    return b.i
}
```

### `impl_methods` — supported

```lir
impl Name { fn m(self) -> T { ... } }
```

Methods receive 'self' (read-only) or 'self: *mut Self' (mutable). Call with value syntax p.m(); the receiver is auto-referenced. There is no 'impl Trait for Type' free-standing method block other than trait impls.

```lir
struct Counter {
    n: i64
}

impl Counter {
    fn value(self) -> i64 {
        return self.n
    }
    fn bump(self: *mut Counter) -> i64 {
        self.n = self.n + 1
        return self.n
    }
}

fn main() -> i64 {
    var c = Counter { n: 0 }
    c.bump()
    return c.value() * 10 + c.bump()
}
```

### `trait_dyn` — supported

```lir
trait T { fn m(self) -> T }
struct S { .. }
impl T for S { fn m(self) -> T { ... } }
fn f(x: dyn T) -> T
```

Dynamic dispatch through a 'dyn Trait' parameter. Every declared method must be implemented; missing methods are a compile error. Values are passed by value and the vtable is selected at the call site.

```lir
trait Area {
    fn area(self) -> i64
}

struct Square {
    side: i64
}

impl Area for Square {
    fn area(self) -> i64 {
        return self.side * self.side
    }
}

fn measure(shape: dyn Area) -> i64 {
    return shape.area()
}

fn main() -> i64 {
    let s = Square { side: 3 }
    return measure(s)
}
```

### `type_alias` — supported

```lir
type Alias = i64
```

Plain alias; the alias name is interchangeable with the aliased type.

```lir
type Count = i64

fn main() -> i64 {
    let c: Count = 4
    return c
}
```

### `bounded_range_type` — supported

```lir
type Percent = i64 range 0..100
```

Bounded integer type. Constant assignments outside the range are compile errors (LIR-E3004); dynamic values are not trapped by this type alone.

```lir
type Percent = i64 range 0..100

fn main() -> i64 {
    let p: Percent = 42
    return p
}
```

### `generics` — supported

```lir
fn id<T>(x: T) -> T
struct Box<T> { v: T }
id<i64>(3)
Box<i64> { v: 3 }
```

Monomorphized generics: instantiate explicitly with <T> at call/construction sites. Nested generic arguments such as Option<Option<i64>> do not parse because '>>' lexes as a shift; bind an alias first.

**Avoid:** Option<Option<i64>>, Vec<Vec<i64>> (nested '>>')

```lir
struct Box<T> {
    v: T
}

fn id<T>(x: T) -> T {
    return x
}

fn main() -> i64 {
    let b = Box<i64> { v: 5 }
    return id<i64>(b.v)
}
```

### `import` — supported

```lir
import core
import math
import std::crypto
import "../lib/util.lir"
```

Resolves to an embedded std module (core, io, os, sys, net, crypto, json, math, str, algo, testing, collections, hash, fmt, time, http), to a sibling/local .lir file, or to a quoted path. Members are unqualified after import. An unknown name that is not a local file stops compilation with LIR-E4004 and a suggestion.

**Avoid:** import MyLib (PascalCase), import lib.rs

```lir
import math

fn main() -> i64 {
    return factorial_i64(5)
}
```

### `pub` — legacy

```lir
pub fn f() -> T { ... }
```

Accepted and ignored: LIR has no module privacy; every declaration in an imported file is visible.

**Prefer:** fn (privacy is not implemented)

```lir
pub fn helper() -> i64 {
    return 1
}

fn main() -> i64 {
    return helper()
}

```

### `extern_ffi` — unsupported

```lir
extern fn puts(s: string) -> i64
```

There is no C FFI declaration syntax yet. Use the @syscall/@open/@write family, or compile with --emit-c and link in C.

**Avoid:** extern fn / extern "C" blocks

### `module_file` — unsupported

```lir
mod foo
```

Modules are files reached through 'import', not 'mod' declarations.

**Avoid:** mod foo { ... }

## Statements

### `let` — supported

```lir
let x = value        let x: i64 = value
```

Immutable binding; the annotation is optional and drives type checking. Re-declaring the same name in the same scope is an error (LIR-E3003); use a new scope to shadow.

**Avoid:** let x: i64;  (declaration without initializer)

```lir
fn main() -> i64 {
    let a = 2
    let b: i64 = 3
    return a * b
}
```

### `let_mut` — supported

```lir
let mut x = value
```

Mutable local binding. 'var' is accepted as a legacy synonym for 'let mut'.

**Prefer:** let mut

**Avoid:** let x = 0; x = 1  (immutable binding)

```lir
fn main() -> i64 {
    let mut total = 0
    total = total + 5
    total += 2
    return total
}
```

### `var` — legacy

```lir
var x = value
```

Legacy synonym of 'let mut'. Prefer 'let mut' so mutation is explicit at the declaration site.

**Prefer:** let mut

```lir
fn main() -> i64 {
    var x = 1
    x = 2
    return x
}
```

### `const_local` — supported

```lir
const NAME = constant_expression
```

Compile-time constant usable inside a function body; the value must be knowable at compile time.

```lir
fn main() -> i64 {
    const N = 2 ** 5
    return N
}
```

### `assignment` — supported

```lir
x = v  x += v  x -= v  x *= v  x /= v  x %= v  x **= v  x &= v  x |= v  x ^= v  x <<= v  x >>= v
```

Targets: local variables, struct fields, pointer dereferences and array elements. Assigning to an immutable binding or while it is borrowed is an error.

```lir
fn main() -> i64 {
    let mut x: i64 = 8
    x += 2
    x *= 3
    x >>= 1
    return x
}
```

### `if_elif_else` — supported

```lir
if cond { } elif cond { } else { }
```

Blocks are always required. Conditions must be bool; '=' inside a condition is reported with a did-you-mean-'==' hint. 'if' is also an expression that yields a value (see if_expression).

**Avoid:** if a = 1 { }  |  if x > 0 (no braces)

```lir
fn grant(score: i64) -> i64 {
    if score > 90 {
        return 3
    } elif score > 50 {
        return 2
    } else {
        return 1
    }
}

fn main() -> i64 {
    return grant(95) * 100 + grant(10)
}
```

### `unless` — supported

```lir
unless cond { } else { }
```

Negated 'if' (Elixir-style). It is a value expression as well. Prefer 'if !cond' for audiences unfamiliar with LIR.

**Prefer:** if !cond

```lir
fn main() -> i64 {
    let x = 0
    unless x == 0 {
        return 100 / x
    } else {
        return 0
    }
}
```

### `while` — supported

```lir
while cond { }
```

Pre-test loop. Provide loop progress: an infinite body that freezes its condition variables is rejected, and break/continue are not allowed inside 'defer'.

```lir
fn main() -> i64 {
    let mut i = 0
    while i < 5 {
        i += 1
    }
    return i
}
```

### `loop` — supported

```lir
loop { ... break }
```

Unconditional loop; exits only through break/return. There are no labels and no 'break value'.

**Avoid:** 'outer: loop { break 'outer }  (no labels)

```lir
fn main() -> i64 {
    let mut n = 0
    loop {
        n += 1
        if n == 3 {
            break
        }
    }
    return n
}
```

### `until` — supported

```lir
until cond { }
```

Runs the body until the condition becomes true. Prefer 'while !cond' for cross-language readers.

**Prefer:** while !cond

```lir
fn main() -> i64 {
    let mut i = 0
    until i >= 3 {
        i += 1
    }
    return i
}
```

### `for_range` — supported

```lir
for i in start..end { }
for i in start..=end { }
```

'..' excludes the end bound, '..=' includes it. Bounds must be integers; both are evaluated once, before the first iteration. The loop variable is immutable.

```lir
fn main() -> i64 {
    let mut sum = 0
    for i in 0..4 {
        sum += i
    }
    for i in 4..=4 {
        sum += i
    }
    return sum
}
```

### `for_in` — supported

```lir
for v in array { }
for c in text { }
```

Iterates a dynamic array (@array_new) or a string byte by byte. The loop variable is the element value. There is no index/value pair form.

**Avoid:** for i, v in items  (index is not supported)

```lir
fn main() -> i64 {
    let items = @array_new(4, 8)
    @array_push(items, 5)
    @array_push(items, 6)
    let mut sum = 0
    for v in items {
        sum += v
    }
    return sum
}
```

### `break_continue` — supported

```lir
break
continue
```

Only inside loops, never inside a 'defer' block, and there are no labelled variants.

```lir
fn main() -> i64 {
    let mut sum = 0
    for i in 0..10 {
        if i == 5 {
            break
        }
        if i % 2 == 0 {
            continue
        }
        sum += i
    }
    return sum
}
```

### `return` — supported

```lir
return value
return
```

A trailing expression without 'return' is also accepted in value functions; explicit 'return' is the canonical style.

```lir
fn sign(x: i64) -> i64 {
    if x < 0 {
        return -1
    }
    return 1
}

fn main() -> i64 {
    return sign(-5) + sign(5)
}
```

### `defer` — supported

```lir
defer statement   defer { block }
```

Runs on every exit from the enclosing scope, in LIFO order. break/continue/return are rejected inside a deferred block.

```lir
fn main() -> i64 {
    defer println("second")
    defer println("first")
    return 0
}
```

### `guard_else` — supported

```lir
guard cond else { return ... }
```

Early-exit helper: the else block must leave the function. It does not bind values and does not support 'guard let'.

```lir
fn ratio(a: i64, b: i64) -> i64 {
    guard b != 0 else {
        return -1
    }
    return a / b
}

fn main() -> i64 {
    return ratio(9, 3) * 10 + ratio(1, 0)
}
```

### `unreachable` — supported

```lir
unreachable
```

Marks a path that must not be taken; reaching it traps at runtime.

```lir
fn main() -> i64 {
    let x = 1
    if x == 1 {
        return 0
    }
    unreachable
}
```

### `unsafe_block` — unsupported

```lir
unsafe { ... }
```

Rejected: raw pointer work is expressed with the *T / @read_* / @write_* builtins instead of an unsafe block.

**Avoid:** unsafe { }

### `asm_block` — unsupported

```lir
asm("...")
```

Rejected: there is no inline assembly. Use @syscall or --emit-c plus a C translation unit.

**Avoid:** asm("nop")

## Expressions

### `struct_init` — supported

```lir
Name { field: value, field2: value2 }
```

All declared fields must be listed; commas are required inside the braces.

```lir
struct P {
    a: i64
    b: i64
}

fn main() -> i64 {
    let p = P { a: 1, b: 2 }
    return p.a + p.b
}
```

### `if_expression` — supported

```lir
let v = if cond { 1 } else { 2 }
```

Both branches must produce a value of the same type; an 'else' branch is mandatory when a value is used.

```lir
fn main() -> i64 {
    let flag = 7 > 3
    let v = if flag { 10 } else { 20 }
    return v
}
```

### `match` — supported

```lir
match value { pattern => expr, ... }
```

Expression form: arms are comma separated and produce a value. Matching must be exhaustive: integers need a '_' (or 'else') arm, enums need every variant or a fallback, bools may cover true/false.

```lir
fn classify(n: i64) -> i64 {
    return match n {
        0 => 100,
        1..=9 => 10,
        v if v > 100 => 1000,
        _ => 0,
    }
}

fn main() -> i64 {
    return classify(0) + classify(5) + classify(500) + classify(-3)
}
```

### `operators` — supported

```lir
a + b - c * d / e % f ** g  |  a & b | c ^ d << e >> f  |  a == b != c < d <= e > f >= g
```

'**' is right-associative integer power and binds tighter than unary minus. Arithmetic wraps modulo 2^64 (no overflow trap); division by zero and out-of-range shifts trap. Precedence: '**' > unary > '* / %' > '+ -' > shifts > '&' > '^' > '|' > comparisons > '&&' > '||' > ternary > assignment.

```lir
fn main() -> i64 {
    let a = 2 + 3 * 4
    let b = 2 ** 3 ** 2
    let c = (5 & 3) | (8 ^ 1) << 1
    return a + b + c
}
```

### `boolean_operators` — supported

```lir
a and b   a or b   a && b   a || b   !a
```

'and'/'or' are the documented spellings; '&&' and '||' are exact synonyms. 'not' is NOT a keyword.

**Avoid:** not x  (use !x)

```lir
fn main() -> i64 {
    if true and !false {
        return 1
    }
    if false || true {
        return 2
    }
    return 0
}
```

### `ternary` — supported

```lir
cond ? a : b
```

Shorthand for a two-armed if-expression. Both sides must have the same type.

```lir
fn main() -> i64 {
    let x = 7
    return x % 2 == 0 ? 100 : 200
}
```

### `cast_as` — supported

```lir
value as u8    value as i64    value as f64
```

Integer casts narrow by keeping the low bits (300 as u8 == 44). Float to integer truncates toward zero and traps on NaN/out-of-range. Integer to float preserves signedness. There is no implicit numeric conversion.

**Avoid:** implicit widening: let x: i64 = a_i32  (write 'as i64')

```lir
fn main() -> i64 {
    let wide: i64 = 300
    let narrow = wide as u8
    let back = narrow as i64
    let f = 2.75
    return back + (f as i64)
}
```

### `string_literal` — supported

```lir
"plain"  "tab\there\n"  "quote\"inside"
```

UTF-8, immutable, length-prefixed. Escape sequences: \n \t \r \\ \" \0. Concatenate with '+', compare with '==', index with s[i] (byte value), read s.len.

```lir
fn main() -> i64 {
    let s = "lir" + "lang"
    println(s)
    if s == "lirlang" {
        return s.len
    }
    return 0
}
```

### `string_interpolation` — supported

```lir
"sum = {a + b}"   "len={s.len}"
```

Any expression inside { } is interpolated. Literal braces must be escaped as \{ and \}. Format specifiers such as {x:#x} are NOT supported (they print literally); use a formatting helper from std::fmt instead.

**Avoid:** println("{42:#x}")  (no format specifiers)

```lir
fn main() -> i64 {
    let a = 2
    let b = 3
    println("{a}+{b}={a + b}")
    return 0
}
```

### `char_literal` — supported

```lir
'A'   '\n'
```

A char literal is an i64 code point value. There is no distinct 'char' type (annotating with 'char' is rejected).

**Avoid:** let c: char = 'A'  (no char type)

```lir
fn main() -> i64 {
    let c = 'A'
    return c - 64
}
```

### `numeric_literals` — supported

```lir
123  0xFF  0b1010  0o17  1_000  1.5  2.5e3
```

Decimal, hex, binary, octal with '_' separators. Integer literals type-check against their context inside the i64 range; a float literal needs a float context (a bare '1' is not a float).

```lir
fn main() -> i64 {
    let a = 0xFF
    let b = 0b1010
    let c = 1_000
    return a + b + c
}
```

### `array_literal` — supported

```lir
[1, 2, 3]   [value; count]
```

Fixed-size array on the stack; index with a[i] (runtime bounds-checked, out of range traps). Use @array_new/@array_push for growable arrays.

**Avoid:** [[1,2],[3,4]]  (nested array literals do not type-check)

```lir
fn main() -> i64 {
    let a = [10, 20, 30]
    let zeros = [0; 2]
    return a[1] + zeros[0]
}
```

### `dynamic_array` — supported

```lir
@array_new(capacity, elem_size)  @array_push(a, v)  @array_get(a, i)  @array_len(a)  @array_free(a)
```

Heap array of 8-byte slots by default. @array_get is bounds-checked and traps out of range. Free with @array_free (compile-time UAF/double-free analysis covers straight-line code).

```lir
fn main() -> i64 {
    let a = @array_new(8, 8)
    @array_push(a, 4)
    @array_push(a, 5)
    let n = @array_len(a)
    let sum = @array_get(a, 0) + @array_get(a, 1)
    @array_free(a)
    return n * 10 + sum
}
```

### `tuple` — supported

```lir
(1, true)   t.0   let (a, b) = pair
```

Tuples hold up to 8 fields in 8-byte slots; field access is t.0 ... t.7. Destructuring is supported in 'let'. Field types keep their width/signedness.

**Avoid:** (1,2,3,4,5,6,7,8,9)  (max 8 fields)

```lir
fn pair() -> (i64, bool) {
    return (7, true)
}

fn main() -> i64 {
    let (value, ok) = pair()
    if ok {
        return value
    }
    return 0
}
```

### `question_mark` — supported

```lir
let v = fallible()?
```

Propagates None/Err to the enclosing function, whose return type must be Option/Result. Also see '??' for a default value.

```lir
fn fetch(ok: bool) -> Option<i64> {
    if !ok {
        return None
    }
    return Some(9)
}

fn twice(ok: bool) -> Option<i64> {
    let v = fetch(ok)?
    return Some(v * 2)
}

fn main() -> i64 {
    return match twice(true) {
        Some(v) => v,
        None => 0,
    }
}
```

### `coalesce` — supported

```lir
let v = maybe ?? fallback
```

Evaluates to the Option payload when present, otherwise to the fallback expression.

```lir
fn main() -> i64 {
    let present: ?i64 = Some(3)
    let missing: ?i64 = None
    return (present ?? 7) * 10 + (missing ?? 7)
}
```

### `closure` — supported

```lir
let f = |x: i64| x + 1
let g = || 7
let h = |x: i64| -> i64 { return x }
```

Pipe-delimited lambdas with capture by value of surrounding locals. '||' introduces a no-argument closure. A closure body may be an expression or a block.

**Avoid:** |x|... , fn(x: i64) -> i64 { }  (closures are not 'fn' literals)

```lir
fn main() -> i64 {
    let step = 2
    let add = |x: i64| x + step
    let seven = || 7
    return add(seven())
}
```

### `method_call` — supported

```lir
receiver.method(args)
```

Methods come from 'impl'. Field access and method calls share syntax, so a struct field that has the same name as a method is ambiguous (methods win).

```lir
struct Bag {
    n: i64
}

impl Bag {
    fn doubled(self) -> i64 {
        return self.n * 2
    }
}

fn main() -> i64 {
    let b = Bag { n: 6 }
    return b.doubled()
}
```

### `named_arguments` — supported

```lir
calc(2, code: 9)   calc(code: next(), a: next())
```

Named/out-of-order arguments are allowed on direct free-function calls only. Evaluation follows source order. Defaults may reference global constants.

**Avoid:** named arguments on method calls or builtins

```lir
fn box(a: i64, b: i64 = 3) -> i64 {
    return a * 10 + b
}

fn main() -> i64 {
    return box(1) + box(b: 5, a: 2)
}
```

### `list_comprehension` — supported

```lir
[expr for v in iterable]
[expr for v in start..end]   [expr for v in a..b if cond]
```

Builds a dynamic array from a range (with optional '..='), an array or a string, optionally filtered with 'if'. The result is a heap array; free it with @array_free.

```lir
fn main() -> i64 {
    let squares = [i * i for i in 0..4]
    let evens = [i for i in 0..10 if i % 2 == 0]
    let a = @array_len(squares)
    let b = @array_len(evens)
    @array_free(squares)
    @array_free(evens)
    return a * 10 + b
}
```

### `map_literal` — supported

```lir
let m = #{ "key": 1 }
```

Literal map construction; '#' followed by '{' is the disambiguator. The same as @map_new + @map_set.

```lir
fn main() -> i64 {
    let m = #{ "a": 3 }
    let v = @map_get(m, "a")
    @map_free(m)
    return v
}
```

### `spawn` — supported

```lir
let h = spawn worker(arg)
let h2 = spawn { body }
@thread_join(h)
```

Starts an OS thread (host targets only: x86_64/aarch64/riscv64 Linux, macOS, Windows, FreeBSD). The thread body may take one i64 argument passed by value; spawn { ... } and closures take none. Passing pointers to locals into a thread is rejected. Join with @thread_join, which yields the body's return value. wasm32-wasi has no OS threads: the compiler rejects thread/channel builtins there with LIR-E7004.

```lir
fn worker(arg: i64) -> i64 {
    return arg * 3
}

fn main() -> i64 {
    let h = spawn worker(14)
    return @thread_join(h)
}
```

### `channel` — supported

```lir
let c = @chan_new(capacity)
@chan_send(c, v)  @chan_recv(c)  @chan_close(c)
```

Bounded MPMC channel of 8-byte values. @chan_recv blocks until a value is available. Requires a host target with OS threads: wasm32-wasi rejects it with LIR-E7004.

```lir
fn main() -> i64 {
    let c = @chan_new(1)
    @chan_send(c, 6)
    let v = @chan_recv(c)
    @chan_close(c)
    return v
}
```

### `atomic` — supported

```lir
@atomic_add(ptr, v)   @atomic_cas(ptr, old, new)
```

Sequentially consistent operations on 8-byte aligned memory. @atomic_add returns the previous value.

```lir
fn main() -> i64 {
    let slot = @malloc(8)
    @atomic_add(slot, 2)
    let v = @atomic_add(slot, 3)
    @free(slot)
    return v
}
```

### `comptime` — supported

```lir
comptime fn f(n: i64) -> i64 { ... }
const V = f(10)
let w = comptime(2 + 3)
```

Compile-time evaluation of pure constant expressions and comptime functions. Loops and recursion are supported with fixed bounds; I/O and runtime values are not.

```lir
comptime fn fib(n: i64) -> i64 {
    if n <= 1 {
        return n
    }
    return fib(n - 1) + fib(n - 2)
}

const TENTH = fib(10)

fn main() -> i64 {
    return TENTH
}
```

### `pipe_operator` — unsupported

```lir
value |> f
```

Rejected: the right-hand side of '|>' must be a call, and plain values are not callable.

**Avoid:** 5 |> 3   |   x |> f(...)  (supply the receiver explicitly)

### `async_await` — unsupported

```lir
async fn f() -> T   let v = await g()
```

No async runtime. Use OS threads (spawn/@thread_create) and channels (@chan_*) instead.

**Avoid:** async fn / await

## Types

### `option` — supported

```lir
fn f() -> Option<i64> { return Some(1) }
let x: ?i64 = None
```

Some(v)/None are context-typed: 'None' needs a typed local, return type or '?' context (a bare 'let x = None' is rejected with 'add type annotation'). Read the payload with match or '?'. Note '?i64' is also accepted as a type spelling.

**Avoid:** let x = None  (no context) | Option<i64> { .. } struct syntax

```lir
fn find(ok: bool) -> Option<i64> {
    if ok {
        return Some(5)
    }
    return None
}

fn main() -> i64 {
    return match find(true) {
        Some(v) => v,
        None => 0,
    }
}
```

### `result` — supported

```lir
fn f() -> Result<i64, i64> { return Ok(1) }
let v = g()?
```

Ok(v)/Err(e) with '?' propagation to the caller. '??' supplies a default for Option. The error payload is 8 bytes (i64 or pointer).

```lir
fn step() -> Result<i64, i64> {
    return Ok(4)
}

fn run() -> Result<i64, i64> {
    let v = step()?
    return Ok(v + 1)
}

fn main() -> i64 {
    return match run() {
        Ok(v) => v,
        Err(e) => e,
    }
}
```

### `pointer` — supported

```lir
*T   *mut T   &value   &mut value   *p = v   p.field
```

Typed pointers to locals, structs and heap memory. '&x' borrows read-only, '&mut x' borrows mutably and blocks reads/writes of x while live. Returning a pointer to a local is a compile error. Raw addresses use @ptr_add/@read_*/@write_*.

**Avoid:** returning &local  (dangling) | *p arithmetic without @ptr_add

```lir
struct Cell {
    v: i64
}

fn bump(c: *mut Cell) -> i64 {
    c.v = c.v + 1
    return c.v
}

fn main() -> i64 {
    var c = Cell { v: 4 }
    return bump(&mut c)
}
```

### `slice_type` — partial

```lir
fn first(items: []i64) -> i64
```

The '[]T' spelling parses and type-checks, and a dynamic array can be passed to it, but there is no slice-of-slice slicing operator and no '.len' on slices (use @array_len on the array).

**Avoid:** s[a..b]  (no slice ranges)

```lir
fn first(items: []i64) -> i64 {
    return items[0]
}

fn main() -> i64 {
    let a = @array_new(4, 8)
    @array_push(a, 9)
    return first(a)
}
```

### `fn_pointer` — supported

```lir
let f: fn(i64) -> i64 = name
apply(f, 3)
```

Function values are first class: pass named functions, store them in locals, and call them through the binding. Struct fields cannot hold them (the field is then read as a method).

```lir
fn triple(x: i64) -> i64 {
    return x * 3
}

fn apply(f: fn(i64) -> i64, v: i64) -> i64 {
    return f(v)
}

fn main() -> i64 {
    let f: fn(i64) -> i64 = triple
    return apply(f, 4)
}
```

### `map` — supported

```lir
let m = @map_new()
@map_set(m, key, v)  @map_get(m, key)  @map_has(m, key)  @map_del(m, key)
```

Hash map with i64 or string keys depending on the first key used; keys are hashed with a per-process secret (HashDoS safe). @map_get returns 0 for a missing key: check @map_has first.

**Avoid:** @map_get without @map_has  (missing keys yield 0)

```lir
fn main() -> i64 {
    let m = @map_new()
    @map_set(m, 1, 40)
    @map_set(m, 2, 2)
    let total = @map_get(m, 1) + @map_get(m, 2)
    @map_free(m)
    return total
}
```

### `integer_types` — supported

```lir
i8 i16 i32 i64 u8 u16 u32 u64 isize usize
```

All are 8-byte slots internally; annotations drive signedness/width checks and casts. i128/u128/i54-style widths do not exist.

**Avoid:** i128 / u128

```lir
fn main() -> i64 {
    let a: u8 = 200
    let b: i32 = -5
    let c: usize = 3
    return (a as i64) + (b as i64) + (c as i64)
}
```

### `float_types` — partial

```lir
f64   f32
```

Arithmetic, comparisons and casting work; float literal values are stored as binary64 and 'f32' annotations accept float literals only through arithmetic contexts (a bare integer literal is not a float). Floats print with printFloat/printlnFloat.

**Avoid:** let a: f64 = 1   (use 1.0)

```lir
fn main() -> i64 {
    let a = 1.5
    let b = 2.5
    printFloat(a + b)
    return 0
}
```

### `void_never` — supported

```lir
fn f() { }          fn g() -> never { exit(1) }
```

A function without '-> T' returns void. 'never' marks functions that do not return normally (exit/panic).

```lir
fn log() {
    println("log")
}

fn stop() -> never {
    exit(3)
}

fn main() -> i64 {
    log()
    return 0
}
```

### `bool_type` — supported

```lir
true   false   let flag: bool = true
```

A bool is a distinct type; it does not implicitly convert to i64. Use (a and b), comparisons, or @signum for arithmetic keys.

**Avoid:** let n: i64 = true  |  printInt(true)

```lir
fn main() -> i64 {
    let flag: bool = 3 < 4
    if flag {
        return 1
    }
    return 0
}
```

## Attributes

### `attr_test` — supported

```lir
#[test]
fn t() { @assert_eq(1, 1) }
```

Marks a test function collected by 'lir test'. Test functions take no parameters and do not need main.

```lir
#[test]
fn adds() {
    @assert_eq(2 + 2, 4)
}
```

### `attr_inline` — supported

```lir
#[inline]
```

Inline hint for the optimizer. #[cold] is the inverse hint.

```lir
#[inline]
fn fast(x: i64) -> i64 {
    return x * 2
}

fn main() -> i64 {
    return fast(3)
}
```

### `attr_cold` — supported

```lir
#[cold]
```

Marks a rarely executed function so hot paths stay compact.

```lir
#[cold]
fn fail() -> i64 {
    return -1
}

fn main() -> i64 {
    return fail() + 1
}
```

### `attr_pure` — supported

```lir
#[pure]
fn f(x: i64) -> i64 { ... }
```

Declares a function free of side effects. Calling a printing/allocating builtin inside a pure function is rejected, which lets the optimizer CSE identical calls.

**Avoid:** println(...) inside a #[pure] function

```lir
#[pure]
fn square(x: i64) -> i64 {
    return x * x
}

fn main() -> i64 {
    return square(7)
}
```

### `attr_pre` — supported

```lir
#[pre(condition)]
#[post(condition)]
```

Hoare-style contract checked at compile time when arguments are constant (a statically violated call fails with 'precondition violation'), otherwise as a runtime assertion.

**Avoid:** requires/ensures keywords  (use #[pre]/#[post])

```lir
#[pre(b != 0)]
fn divide(a: i64, b: i64) -> i64 {
    return a / b
}

fn main() -> i64 {
    return divide(9, 3)
}
```
