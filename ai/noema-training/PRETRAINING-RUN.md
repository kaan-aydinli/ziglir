# Expanded synthetic pretraining run

Run date: 2026-11-24 (UTC)

## Dataset and training

The corpus is generated by `build_synthetic_pretrain.mjs` using Node.js only. It
contains deterministic Turkish arithmetic and unit-conversion examples with
answers computed by the generator. It is synthetic task data, not human-authored
or general-knowledge prose.

The default run produced **4,096,000,000 UTF-8 payload bytes** in **4,096
records** of 1,000,000 bytes each, with 4,095 standalone `---` separators and
**41,992,367 example lines**. The separated TXT measured 4,096,020,475 bytes;
the length-prefixed `.nbin` stream measured 4,096,040,960 bytes. Reproduce using:

```sh
node ai/noema-training/train_synthetic_auto.mjs
```

`RECORDS` and `RECORD_BYTES` are configurable. The 4,096-record default is a
corpus-size choice, not a maximum; there is no hard-coded record ceiling. The
pipeline sizes exemplar storage and training from the full metadata record count,
preflights disk space, and is ultimately limited by host address space, memory,
disk and LIR's integer representation.

The `pretrain_large_latest.nps` alias points to v008. Temporary TXT, `.nbin`,
manifest, metadata and staged checkpoint files were cleaned after publication;
the generated multi-gigabyte corpus is not checked into Git. Promotion validated
the candidate before replacing the live alias.

## Promotion and live-serving results

The candidate passed exact retrieval checks for all 16 task families (addition,
subtraction, multiplication, division, percentages, km-to-m, minutes-to-seconds,
hours-to-minutes, m-to-cm, kg-to-g, L-to-mL, cm-to-mm, days-to-hours,
weeks-to-days, hours-to-seconds and m-to-km), supplemented with five record-
spread probes (the first family probe is also the first spread probe). Exact
substring lookup produced similarity 1.0 for matched prompts; that score
indicates lexical identity, not semantic confidence.

Five out-of-domain probes all abstained under the 0.22 score threshold plus
whole-token overlap guard. These are effective candidate scores after lexical
gating; a candidate without whole-token overlap is excluded from scoring:

| Probe | Similarity |
|---|---:|
| `Trabzon'da bugün hava nasıl?` | 0 |
| `Fotosentez bitkilerde nasıl gerçekleşir?` | 0 |
| `Bu programdaki bellek sızıntısını bul ve düzelt.` | 0 |
| `İnsan kalbinin temel görevi nedir?` | 0.203844 |
| `Türkiye'nin başkentini ve konumunu açıkla.` | 0 |

After publication, the regular `trained` adapter and running `/api/chat` route
loaded version 8. The adapter reported 4,096 records, 4,096,000,000 training
bytes and 4,096 exemplars. For `802191 metre kaç santimetredir?`, the API returned
`Soru: 802191 metre kaç santimetredir? Yanıt: 802191 × 100 = 80219100; uzunluk
80219100 santimetredir.` (104 generated bytes, retrieval similarity 1.0). The shorter in-domain prompt
`802191` also returned the stored answer at similarity 0.410391—above the
configured 0.22 threshold but below the previous 0.50 value. An out-of-domain
photosynthesis query returned `generatedBytes=0` and effective similarity 0
after the token-overlap gate.

## Quality scope and evidence

The corpus is about four times larger by records and payload than the previous
999 MB run, retains 4,096 rather than 999 exemplars, and doubles the deterministic
task families from eight to sixteen. Every payload byte in all 4,096 records was
processed by the pretraining path. The retrieval ring intentionally retains only
the first eligible line from each 1 MiB record—not all 41.99 million generated
lines—so retrieval coverage is a bounded sample of the full training data.
Exact-match retrieval and abstention checks passed. This does **not** establish
generalization, natural-language quality or
reasoning: the corpus is synthetic, examples are formulaic, and the model still
returns stored lines rather than calculating new answers. The larger retrieval
index is also more expensive to scan per query.

Pretraining tests 46–62 passed on native; test 53 used `-O1` because of the
known `-O2` checkpoint-test codegen issue. Tests 47, 56, 57 and 62 passed on VM
and C; test 62 now has 9/9 checks on all three backends. No Python command or
Python test orchestrator was used.
